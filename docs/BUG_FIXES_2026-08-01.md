## 已确认并修复的实际 Bug

### 1. Runtime 密钥迁移与发布链不兼容

修复前：

- 现有 `2.0.2-r1` 的内容密钥使用旧管理员密码派生密钥加密。
- 新 Runtime Worker 只接受独立的原始 32 字节 `RUNTIME_MASTER_KEY`。
- 永久发布工具仍用旧密码派生算法生成运行包。
- 永久发布工作流把 release 提交到 `v2-server-authoritative`，线上 Worker从 `main` 读取 release。
- 发布工作流还会写入旧 `ADMIN_PASSWORD` 并部署旧分支 Worker。

修复后：

- Runtime Worker 优先使用独立 `RUNTIME_MASTER_KEY` 解密新 release。
- 当前 `2.0.2-r1` 通过旧密码兼容通道继续工作。
- `build_release.py` 只接受 64 位十六进制或 Base64 编码的原始 32 字节主密钥，不再从密码派生。
- 永久发布工作流在 `main` 构建、签名并提交 release。
- release 进入 `main` 后由主分支 Runtime 部署工作流发布，不再部署旧分支代码。
- 自动测试覆盖新 raw-key release 和旧 `2.0.2-r1` 密钥迁移路径。

### 2. 现有 Secret 迁移会直接阻断部署

仓库当前确认存在的 Repository secrets：

- `CLOUDFLARE_ACCOUNT_ID`
- `CLOUDFLARE_API_TOKEN`
- `LICENSE_ADMIN_PASSWORD`

修复前，新工作流强制要求另建 `ADMIN_LOGIN_SECRET`。按仓库现状直接合并会在 Secret 检查阶段失败。

修复后：

- `ADMIN_LOGIN_SECRET` 缺少时自动读取现有 `LICENSE_ADMIN_PASSWORD`，后台登录密码保持不变。
- `LEGACY_RUNTIME_PASSWORD` 缺少时自动读取现有 `LICENSE_ADMIN_PASSWORD`。
- `RELEASE_SIGNING_PASSWORD` 缺少时自动读取现有 `LICENSE_ADMIN_PASSWORD`。
- 不需要查看、重置或重新哈希旧密码。
